# External Core v0.6 — physical qualification checklist

**Status: source compiled, production promotion NOT accepted.** Signed installed #710 predates the required host services. This document is a device-test protocol, not permission to skip existing protection or to assume that a green compile means a working external Core. Only the user initiates normal signed APK Builder builds, Android installs and protected component trials.

## Gate H — new host before external trial
- Manually build/install signed RiftOS from the RiftOS/Builder main heads containing `RiftHostCapabilityUiV1`, `RiftHostBuildLocalV1`, and the existing versioned QuickJS/NativeBuffer primitives. Confirm green Builder Bash/Python source contracts and Android compilation, exact source SHA and RiftOS normal desktop startup.
- Open dedicated **RiftOS Recovery** directly after an Android force-stop, and confirm Core/Shell still embedded, working backups absent (unless previously accepted), controls disabled appropriately, file picker opens/cancels, no automatic install.
- Confirm all original installed RAPPs and QuickJS/graphical frames still work, survive app stop/reopen, and no Core/Shell activation occurred. The four legacy RAPPs are JSON/QuickJS; they do NOT prove native-buffer. Separately build/package a valid `native-buffer-v1` RAPP and prove its output using the shared APK host primitive on **embedded Core** first.

## Gate Q — explicit external-Core trial, not release promotion
- Use the **exact freshly compiled independent Core** generated by registered Kotlin + D8 from `external-components/compile-core.json` and 13 source files. Strip all eight compile-only APK host classes. Verify DEX SHA, supported ABI, entrypoint, sealed on-disk bytes, source closure and versioned manifest. Never install placeholder/stale DEX.
- **Only after H passes**, select a locally produced `component.json` and matching DEX via independent Recovery, allow its verifier/stage checks, and explicitly confirm Install. This is an *unaccepted experimental* Core on next start, not a released working Core. Preserve embedded Core and unchanged RAPP files.
- After forced stop/restart, confirm host status reports an external, unaccepted Core and real independent Core process startup (not embedded fallback). If anything fails, open the separate Android Recovery icon and manually restore embedded; do not clear app storage or uninstall.
- Enumerate all four original installed RAPPs with manifest/adapter/permissions, run each appropriate app, verify real Core session generation, input/focus/frame revisions, persistence and stop/reattach across Shell process restarts. Prove both QuickJS and separately installed Rift++ native-buffer app on the external Core.
- Exercise package install/update/uninstall using a disposable test RAPP, including transactional recovery, grant revocation and unchanged unrelated RAPPs. Do not uninstall original apps.
- Exercise scoped filesystem read/write/move/list and explicit consent (allow, deny, timeout, Shell absent), repeat grants, stale reply after package removal, build.local toolchain/compiler/D8 and signing.identity describe/sign/verify using a disposable test app. Clipboard/share/window title UI ticket flow must return a single correctly correlated result; network remains intentionally denied. Check event queues don't advance past pending effects or accept reserved Shell events.
- Force-stop/reopen multiple times, verify Core-selected state and no missing RAPPs/drive files. Confirm a normal graphical Shell can crash/restart while independent Core and sessions survive.

## Gate R — real backup and manual rollback
- After a fully successful Core trial, use the existing device acceptance flow to mark **that exact SHA** accepted. Then install a separately qualified later Core revision through Recovery. Confirm the APK stores **only the last accepted Core** in `core.working-backup.json` and that the matching sealed DEX/receipt remain available.
- From Recovery, explicitly restore the known-good backup, force-stop and restart, and prove installed RAPPs, state, grants, drives, native/JS runtimes and window surfaces. Also test a manual return to the signed embedded migration fallback.
- Only after the real rollback passes may Patch B backup/restore be accepted. The unfinished external graphical Shell and automatic recovery cleanup **Patch C** are independent later gates; no Core trial permits deleting embedded fallback early.

**Do not declare 100% qualification** from compiler/D8, static source checks, a file picker screenshot, or a candidate loading once. Record each gate's actual build number, SHA, screenshot/functional evidence and restore result.

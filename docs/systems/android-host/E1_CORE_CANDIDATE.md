# E1 — External Core Extraction: Source Closure and Independent Candidate

## 2026-10-10 — Fail-safe Core switch infrastructure (LOCAL, UNBUILT)

At the user's request, **the next stable-host APK source patch now carries an optional startup-only switch** (not a live hot-swap). Android host-owned `RiftCoreCandidateSwitch.kt` can inspect a fixed sealed `core-<SHA>.dex` activation record, require a matching private independent qualification receipt (ABI1, exact SHA, entrypoint, complete ownership and inactive-load proof), hash the immutable candidate, enumerate up to 4096 DEX class definitions and reject anything outside the `com.riftos.external.core.` namespace or shadowing the installed APK, then require a separately loaded class implementing the APK-owned `RiftCoreComponentV1`. `RiftHostCoreComponents.initializeAtBoot` falls back to the embedded adapter on absent/invalid/failed candidate; an unaccepted external candidate keeps a durable `core.booting` marker, so the *next* process start revokes its activation and selects embedded after an interruption. `RiftBootstrapComponentStore.resetCoreToEmbedded` removes only that activation pointer/marker and preserves sealed DEX evidence. ContentProvider no longer eagerly starts the embedded Core before Android Application startup. No core binary, activation writer, certificate-qualified receipt producer, Core fully extracted closure or trusted UI approval is shipped at this checkpoint; therefore **the selected Core remains embedded and externalCoreEnabled=false on the next signed APK by default**. A qualification receipt is necessary but alone is **not** evidence of correct independent Core behavior.

The generic `RiftBootstrapHost.start(...)` probe gate remains restricted to `probe`; Shell, MCP/relay and Android lifecycle remain inside the APK. Process death cannot be intercepted by the dead process: fallback occurs on the next startup, not magically while the process is dead. There is **no automatic promotion** or in-process hot-swap. Proper full Core extraction and source dependency closure, host-service capability narrowing, a verified artifact-builder/qualification writer, trusted one-use approval, user-device fallback/negative tests and closure of all direct host→`RiftCoreRuntime` calls are required **before accepting any external Core**. This patch is source-only, has not been Kotlin compiled or device-proven, and MUST NOT be called a completed replaceable Core system.

**Gate:** E1-A started on 2026-10-10. **Not E1 accepted. No separate Core DEX, no external Core load, no runtime selection change.**

## Ownership contract: Core must actually leave the APK

E1 target is a **real independently compiled Core implementation**, *not* an empty DEX wrapper calling embedded `RiftCoreRuntime`, a second Core service with duplicated state, or a DEX containing APK-owned classes that the parent classloader shadows. The future Core candidate must implement the APK-owned `RiftCoreComponentV1` using classes that are not also in the host APK.

- **Permanent host:** `RiftCoreApplication`, `RiftBootstrapHost`, `RiftCoreSurfaceIpcProvider` (protected Binder/UID/PID/signing/size/generation controls), `RiftHostComponentAbiV1` host interface and selection, Android manifest components, one-use privileged consent/recovery boundaries, `RiftCoreShellRecovery`, Android Context/platform capabilities, MCP relay and Android-specific entrypoints.
- **First executable extraction roots:** `RiftCoreRuntime`, `RiftCoreAppLifecycle`, `RiftCoreAppSessions`, `RiftCoreAppSurfaces`, `RiftCoreInputFocus`, `RiftCoreAppExecutor`, `RiftRappManager`. Closure necessarily pulls the RAPP ABI, runtime adapters, build/filesystem services, event queue, executor and other dependencies; it is **not** a seven-file Core module.
- **Current blockers:** `RiftCoreRuntime` still calls Android Context and host status/admin/registry services; package management and build APIs need explicit host callback contracts; the current V1 adapter itself delegates to APK-owned `RiftCoreRuntime`; the exact Gradle Kotlin list still embeds all executable implementation classes. External candidate code must not import or recompile those APK-owned classes under identical binary names.
- **Reproducible audit:** `node scripts/test-e1-core-closure.mjs` inventories the *current* transitive source file references, records host-boundary edges and Android-import files, and verifies E0's embedded-only safety selector. This is a source-risk diagnostic, **not** Kotlin type-checking, DEX compilation, candidate closure certification or dynamic loading.

## E1 acceptance contract (all still pending)

1. Replace broad host Context transfer with a versioned, narrowly privileged host callback/services interface; protect C1.4 exact caller/signer approvals, Binder size and app-generation bounds, and retain the production embedded default.
2. Extract a complete real Core transitive class implementation into an independent source/compilation unit. Compile with explicit Android bootclasspath + V1 ABI-only API stubs, not using the compiled executable APK Core implementation as a runtime crutch.
3. Produce a distinct immutable DEX with compiler/toolchain fingerprint, ABI version, exact entrypoint, every output class and its source ownership, SHA-256 content digest and reproducible revision manifest. Reject missing, unexpected, forbidden or APK-duplicated classes **before staging**. No blanket sibling package classloader exposure.
4. Prove the signed candidate in an isolated disposable, nonprivileged **inactive** verification step: actual DEX loads, ABI matches, known-good operations match a deterministic bounded fixture, and deliberate incorrect SHA, wrong ABI, missing class and duplicate class are rejected. No user RAPP, protected process, grant, system file or active Core changed.
5. Keep `RiftHostCoreComponents.core()` selecting **only embedded**; no Core startup pointer, restart/rollback toggle, admin system effect or production activation until **E2** and explicit approval/device tests.

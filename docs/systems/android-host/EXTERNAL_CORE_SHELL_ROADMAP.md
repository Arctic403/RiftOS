## Objective and non-negotiable operating rules

**Target:** A small, stable Android APK containing platform entrypoints, narrowly scoped host services, protected authorization, verifier/installer, crash supervisor, recovery journal and MCP/relay; independently built, installed, versioned, testable, replaceable real Core and then real graphical RiftShell. Once all *required* host infrastructure is accepted on a manually signed/device-proven APK, routine changes to external Core and Shell use **compile → qualify → stage → disposable test → scoped activate/restart → health-check → promote/rollback** without repacking RiftOS.

This is a **conditional no-repack promise**, not an immediate assertion about current code. An APK rebuild is still necessary for Android manifest/permissions/signing, host callback/ABI changes, missing host capabilities, platform/JNI adapters, host crash supervisor, or eventually removing the embedded implementations. Do **not** call #695 or the pushed E1 source a finished stable-loader host.

**User-controlled boundaries:**
- User manually dispatches every signed RiftOS Builder build, installs and performs/authorizes device acceptance. Do not trigger APK Builder automatically, bypass compiler/preflight/pack/sign verification, or change its existing manual process.
- Source pushes are explicit user-authorized; RiftOS and Riftos-builder are distinct coordinated repositories. Do not directly mutate GitHub outside sanctioned RiftOS MCP/RiftGit.
- Do not advance gates on source-marker/compile-only evidence. Physical install/use, restart and negative cases are required where listed. Stop on failure and preserve known-good revisions.
- **Core and Shell are already separate Android processes.** Externalizing *implementations* is the remaining goal; no duplicate “Core kernel,” extra Core authority or second production app runtime.
- MCP and relay **remain in the Android APK host and survive loss of the foreground Shell**. Android governs package/process sandbox, UID, Activity/Service/ContentProvider lifecycle and permissions. No Linux layer; ordinary RAPPs/runtime providers remain separate from these privileged host components.
- Never allow arbitrary RAPP, a remote tool, or an untrusted DEX to mint qualification receipts, modify activation pointers, impersonate the trusted admin UI or invoke privileged host callbacks. A same-UID DexClassLoader is **not an isolation/security sandbox**.

## Gate H — stabilize permanent Android host and verifiable independent build channel

**H0 — host ownership and safety contract (preparation).** Audit source dependency graph; identify Android-only host declarations: `Application`, protected Core Binder `ContentProvider`, `:riftShell` Activity/process, UI/input/WebView/JNI bridges, package-signer and process identity checks, one-use admin consent, loader, verifier, persistent activation store, version history, crash collector and watchdog, MCP/relay. Design **narrow versioned host callbacks** instead of allowing portable Core unrestricted `Context` or calls into APK-owned `RiftCoreRuntime`. Document the complete host/portable class inventory and strict package/loader namespace; no external class may shadow a host class. Core authority stays in the existing default Android process, and Shell retains its existing `:riftShell` process.

**H1 — independent distribution infrastructure.** Implement reproducible **external** Core/Shell compile → DEX/class/native-ABI preflight → SHA-256/content-addressed immutable install → revision/ABI/compiler fingerprint/entrypoint manifest → exhaustive duplicate/missing/forbidden class scan → safe read-only activation catalogue. Ensure installation, schema migration and journal files are durable/atomic, size/path/symlink bounded, and scoped to this component. Qualification is established only by trusted code performing an actual inactive load/contract/provenance check; never trust a self-declared `completeOwnership` or `inactiveLoadProven` flag. Retain version N-1 and a known-good embedded baseline through migration.

**H2 — guarded startup and external recovery supervisor.** The Core cannot detect its own process death. Put watchdog/boot-loop protection, monotonic attempt budget, previous/active/last-known-good pointers, failure capture and next-start rollback decisions in a **host-controlled survivor/restart path** outside the failing Core execution. Respect Android process start restrictions; no invented always-alive guarantee. A probe that can only detect a synchronous thrown exception does *not* pass H2. Keep Shell and MCP/relay protected from candidate reinitialization. All selections occur on a controlled restart with one selected Core instance and one authoritative RAPP state store—never live class hot swap.

**H3 — host acceptance checkpoint.** User-manual signed Builder + physical device test for the complete host interface, deployment, supervisor and recovery. Prove embedded-default parity, locked-out unauthorized writes/activation, negative corrupted/incompatible DEX, surviving host/relay where Android permits, no second running Core, exact Gradle/Builder/signed-DEX parity, and cold-restart rollback. **After H3** ordinary compatible external component edits should not need APK builds; any uncovered host/ABI/platform gap reopens H gate and may require another user-manual APK build. Do not claim “one more APK guaranteed” before this gate passes.

## Gate C — independently running REAL external Core

**C1 — extract real execution ownership.** Move the complete real Core lifecycle/registry/session/surface/focus/dispatch/package/filesystem and required runtime graph to a separately compiled class closure, with portable namespace and host API only. Remove or replace all host-side direct `RiftCoreRuntime` execution imports before selecting external Core. APK-host Binder still enforces real Shell PID/UID/signer, payload bounds, generation numbers and one-use admin consent; the external Core cannot authorize itself. No fake facade that forwards back to embedded Core; no duplicate singleton registry or Android platform service owner.

**C2 — compile and reject bad candidates.** Produce distinct sealed Core revision(s), verify all classes/resources/dependencies and both ARM variants if native code is involved; record complete compiler/revision/SHA/ABI provenance. Disposable inactive load/contract test must show no APK-owned implementation classes resolve as its “real Core.” Negative tests: bad SHA, mismatched signer/revision/ABI, missing/transitive class, duplicate host class, wrong entrypoint, symlink, oversized DEX, truncated file, rollback-record tampering, replayed/expired admin approval and startup exception. No external production selector flip during qualification.

**C3 — device-prove external Core execution with embedded implementation inactive.**** After explicit user approval for the exact candidate, perform a controlled restart to select external Core and confirm runtime status reports **external verified SHA**. Assert embedded Core initializer/registry/lifecycle not used to serve ANY RAPP, including install/uninstall, C:/D: filesystem, lifecycle, events, capabilities, sessions, timers, queued effects, terminal commands, MCP/relay bridge and Shell IPC. Use runtime entrypoint/trace/classloader provenance plus counter/forbidden-call checks, not just the selector label. Verify multiple RAPPs, foreground/background, process separation, state persistence and shell restart. Do not delete embedded classes to manufacture a misleading pass.

**C4 — intentionally test “no embedded execution.”** During a **separately approved** reversible test, reject/disable embedded Core execution paths without removing the stored fallback version; repeat real-device functional and restart suite. A disposable signed **candidate-host variant without embedded implementation** may be required as the final decisive evidence against accidental references, subject to the manual Builder and installed-device rules. External Core must work because it is complete, not because the parent classloader quietly supplies old Core behavior. If a missing host service is discovered, fix host at H gate; do not bypass safety to claim no-repack completion.

## Gate R — Core version history, full available crash evidence and automatic external rollback

**R1 — promotion only after acceptance.** Trusted admin UI requests stage and separate one-use exact `candidate ID + digest + revision + Core ABI + operation` activation approvals. Maintain **active**, **last-known-good** and **previous** immutable external Core revisions in a durable journal with atomic pointer updates. Do not overwrite or garbage-collect the last good artifact while qualifying a new update. Enforce bounded failures, idempotence and replay denial.

**R2 — crash/failure records.** Persist each update attempt, phase, exact candidate SHA/ABI, exit category, observed Android process/PID, time, bounded exception and full available Java stack, and native tombstone/log reference when the platform actually exposes it. Persist before/after startup checkpoints, include bounded redacted diagnostic hashes and outcome (fallback initiated, completed, failed). Avoid exposing consent bearers, secrets or raw user files. **A full stack/tombstone cannot be guaranteed** for an abrupt native abort/OOM/kill where Android withholds it: record accurately what was available and what was missing; don't report a fabricated “full crash dump.”

**R3 — recovery order.** On rejected or failed new Core update, watchdog/restart path selects **last-known-good external Core N-1 first**; only if that fails safely fall back to embedded Core while it still exists. Prevent crash loops via attempt budget/quarantine and preserve core-owned durable RAPP/workspace state and version-compatible schema migrations/rollback. Core-only and Shell-only recovery must not delete each other's state. Never restart the entire OS when a narrower safe recovery is possible, but acknowledge Android may kill the shared host process; recover at next allowed start.

**R4 — real device failure matrix.** Inject safely bounded startup exception, wrong ABI/hash, process death after startup, crash-loop, corrupted active pointer, interrupted pointer write, stale ticket, last-known-good failure and user-triggered rollback. Verify previous external revision starts, its SHA and state are confirmed, failed SHA quarantined, diagnostics visible and audit durable, Shell reattaches, MCP/relay resumes as Android permits. A simulated thrown exception/journal test does not count as a real process-kill/OS restart proof.

## Gate S — extract, run and recover REAL graphical RiftShell

**S1 — actual graphical extraction.** Keep stable Android `RiftShellActivity`/lifecycle/window/insets/input/IME/WebView adapters in APK; extract real desktop/window manager, taskbar, Start menu, File Explorer UI, browser presentation and native workspace/system app controller to an independent Shell implementation. `RiftShellPresentationV1` alone is a declaration, **not** independent Shell. Ensure no packaged duplicate desktop implementation silently executes, and Shell remains presentation-only; Core and running RAPPs are unaffected by Shell death.

**S2 — external Shell candidate pipeline.** Reuse H's immutable manifest, SHA/ABI/class owner checks, separate signed/exact approval, inactive load, version history and guarded restart in `:riftShell`. User-manual device proof confirms launcher/input/keyboard, window actions and geometry, browser, files, RAPP surfaces, foreground/background, physical Shell PID replacement, original Core PID and RAPP generations retained, and no APK embedded Shell execution. Device-test both 32-bit/64-bit builds when native code changes.

**S3 — Shell recovery parity.** Persist Shell crash details and snapshots before and after update. On failed Shell update, restore prior external Shell N-1 (then embedded Shell only during migration), recreate desktop and reattach to *existing* Core sessions without replaying BOOT or losing Core work. Crash and restart the real graphical `:riftShell` process with scoped explicit device approval; verify Core/relay remain healthy and no crash loop.

## Gate F — remaining native services and minimal APK cleanup

**F1 — reusable services.** Externalize only the services/drivers/runtimes that benefit from independent revision and can honor Android app sandbox/JNI ownership and capability gates. Keep MCP + relay inside the Android APK as required. Do not prematurely replace Android framework loader, native method registrations, WebView process setup or privileged authentication.

**F2 — embedded-removal release.** After **Core + Shell are actually independently device-proven, with embedded variants dormant**, freeze restorable last-known-good external Core/Shell, qualified recovery tools and ABI. Then *and only then* remove embedded executable Core and Shell implementation classes and stale Gradle/Builder hardcoded source/DEX expectations. **Rebuild the APK manually once for this removal**, plus any genuine host/ABI fixes uncovered by the cleanup. Recovery after removal must fall back to a **previously verified external** revision; there is no longer an embedded Core/Shell fallback.

**F3 — final signed integrated acceptance.** Confirm correct Core/Shell external SHA/ABI provenance and no APK duplicate implementation, boot after power cycle, bad update recovery, real process deaths, admin tickets, RAPP install/uninstall/long-running work, C:/D: state, native services, input/IME/browser/file explorer, background/foreground, two CPU ABIs, core and shell independent rollback, diagnostic preservation, no unsupported privilege escalation. Freeze host ABI/release only after all pass. General Python/Node/npm runtime-provider enrollment remains deferred until F3/E5 approved.
